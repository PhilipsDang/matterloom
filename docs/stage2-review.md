# 第二阶段：结构化信息提取与审核

实施日期：2026-11-08。版本：0.2.0。

对应计划 11/9–11/15：完成结构化提取与审核界面，每条结果可以定位原文、修改和标记不确定。本阶段实现已交付；真实浏览器操作、真实 GLM 调用与律师使用反馈仍待验收，不能写成已完成律师验证。

## 当前能力

同一事项的文件分别提取，候选汇集到“事实审核”。可以按类型、审核状态、内容和文件名筛选。点击引用后，右侧打开 PDF 对应页或 DOCX 对应段落/表格单元格，并高亮解析文字；PDF 可切换回真实页面图片。图片上不绘制未经验证的精确框选。

默认本地规则模式，无需 API。可选 GLM 模式通过明确的文字发送许可开启：仅发送本事项待提取文件的解析文字，不发送其他事项、人工审核历史或 evaluation 参考答案。未配置时界面说明原因。没有实际调用外部模型来处理本次样本。

本地规则只识别文字特征和语句线索；GLM 用于更广泛的语义候选提取，实际效果尚未验证。两种模式的候选均必须通过字段与逐字引用校验，再由人审核。模型无权直接确认结果。

## 统一字段

| 字段 | 含义与约束 |
| --- | --- |
| id / matter_id / document_id | 系统生成的记录、事项、文件标识；不得跨事项访问 |
| kind | person / organization / amount / date / event / claim / question |
| label | 可编辑短标题，最多 120 字 |
| value | 一个名称、数值文字或完整陈述，最多 1600 字；保留主张归属、否定、争议与计划语气 |
| normalized_value | 可选规范值；日期为有效 YYYY-MM-DD，金额如 CNY 100000；未知为 null |
| uncertainty | 不确定性说明，最多 800 字，不以虚构置信度替代说明 |
| evidence | 1–8 个引用，每个含 unit_id 和逐字连续原文；单条引用最多 1600 字；本版一条记录的引用限同一文件 |
| citation snapshot | 系统补充文件名、PDF 页序号或 DOCX 段落/表格位置、提取方法、源单元摘要；用户和模型不能伪造这些字段 |
| original / current | 首次提取内容与当前编辑版本分别保存；原始提取不被修改覆盖 |
| status | pending 待审核 / confirmed 已确认 / uncertain 不确定 / excluded 已删除 |
| reviewer_note | 人工修改或确认的说明，最多 1600 字 |
| version / history | 版本号与完整前后版本，用于追踪及防止过期页面覆盖新修改 |
| source_valid / eligible | 原文是否仍匹配；仅已确认且来源有效时 eligible 为 true |

人物或机构的 value 是名称，金额/日期的 value 保留原始表述，事件/主张/问题的 value 保留完整上下文。不把“要求减价”改成“已同意减价”，不把“拟离职日期”改成“劳动关系终止日期”。

规范值校验只能保证格式有效，不能证明语义正确。例如某金额归谁、日期属于哪个事件，仍要对照原文审核。引用存在也不等于引用支持整条结论。

## 审核和更新规则

1. 自动提取与手动补充均为待审核，不能直接进入后续成稿或日程。
2. 在编辑窗口修改内容，并明确选择待审核、已确认、不确定或已删除。标记不确定时需有原因或审核备注。
3. 删除采取保留历史的方式；“已删除”筛选中可以恢复。重新提取不会自动恢复删除项。
4. 完全相同的初始候选及引用去重，保留已有人工修改。不同原文或措辞可能分别保留；不进行自动实体合并、冲突裁决或跨文件责任判断。
5. 重新解析保持原文单元不变时，确认状态保留。原文文字、位置、提取方法或状态改变时，受影响的已确认记录退回不确定并追加历史。
6. 原文变化或暂不可用的旧记录不能确认。重新提取后核对新记录，再删除过时记录；旧引用与人工修改仍可查。
7. 过期编辑窗口保存返回冲突，要求刷新，不能覆盖新版本。同一文件同时只允许一个提取任务。
8. 默认数据目录内新增 extraction_runs、facts、fact_history 三张表；既有事项、原件和原文单元继续保留。运行检查只使用临时数据目录。

## 提取边界

- 本地：常见带角色名称、机构名、阿拉伯数字人民币金额、完整/不完整日期及事件/主张/信息缺口语句。中文大写金额、代词、无角色的人名、复杂表格关系、跨页句子可能遗漏；长行换行仅作启发式处理。
- 日期：相对期限、缺少年份的月日保留原文，不补算；无效公历日期不填规范值。没有实现法定期间计算。
- 扫描：无可读文字时失败并保存失败记录，不能当作“提取完成但无事实”；原件仍可查看。
- 部分解析：只处理可用文字，提取记录标为部分完成。不会掩盖未识别的页或图像。
- GLM：固定官方 HTTPS 接口，禁止跟随重定向；每批约 6000 字，上限 20 批/文件，每请求超时 90 秒。超出限制明确失败，不静默截断。没有自动重试付费请求。
- 模型结果：未知字段、空引用、其他事项/文件引用、改写或拼接的非连续引用都会被拒绝。有效候选可以保留，同时记录拒绝条数；全部无效则失败。模型响应截断、非法 JSON、后续批次失败时，该文件整次新增结果不落库，原有审核不变。之前已发出的调用仍可能收费。
- 审计：记录请求模型标识、返回模型标识、提取规则/字段版本、提示词摘要和运行时间；不在浏览器或日志中暴露密钥。
- 知识库：本版是在事项范围内积累带出处、可审核的信息。跨事项共享、检索问答、自动去重实体与冲突处理不属于本阶段。

## 实际验证

48 项自动测试通过：包含第一阶段 22 项与本阶段 26 项。覆盖来源校验、跨事项隔离、模拟模型异常、修改历史、重提取保留人工修改、并发冲突、原文变化、失败重解析、原数据库升级、扫描无文字及部分覆盖。前端两个 JavaScript 文件通过语法检查。

本地样本检查使用 16 份既有虚构材料，关闭 OCR：

| 模拟事项 | 可提取 / 总文件 | 候选记录 | 引用定位 | 重复提取新增 |
| --- | --- | --- | --- | --- |
| 设备买卖 | 7 / 8 | 76 | 76 条均定位到所引原文 | 0 |
| 劳动事项 | 7 / 8 | 53 | 53 条均定位到所引原文 | 0 |

11 个预设金额和完整日期的字面检查点均找到，包括 A04 跨换行的 10,000 元。全部候选保持待审核。A03 和 B08 是无文字层扫描件，明确报告无法提取。

以上证明基本流程和引用存在性，**不是准确率、召回率、语义支持率或律师效率评估**。样本检查程序与参考答案位于提取器之外，不进入模型输入或候选生成。

```sh

node --check web/app.js
```

## 尚待验收

当前执行环境禁止开启本地网页监听，自动测试浏览器启动也失败。没有通过其他方式绕过限制。因此，本次完成的是服务请求处理和数据流程测试、前端语法与结构检查，未完成真实浏览器交互及视觉验收。GLM 只使用模拟响应验证协议和错误路径，尚未做真实调用。OCR 仍沿用上一阶段未通过真实识别的状态。

在可运行服务的本机启动后，用以下步骤验收：

1. 载入一组模拟案卷，进入“事实审核”，点击本地提取；观察扫描件失败提示及持久化提取记录。
2. 筛选金额，点击合同总价引用；确认右侧 PDF 页序号、文本高亮和原图对应；再核对 DOCX 表格中的金额位置。
3. 修改一条记录并保存为不确定，添加备注；打开修改记录，检查首次提取与修改前后内容。
4. 确认一条记录，删除另一条，重新提取并刷新页面；确认修改和删除状态保留。
5. 从当前原文手动补充一条记录，再审核；切换事项，确认没有上一事项的信息混入。
6. 若启用 GLM，先按英文 README 配置具体模型与密钥，仅使用模拟材料实测；检查返回模型标识、引用和拒绝计数，并记录误抽、漏抽与不支持的结论。
